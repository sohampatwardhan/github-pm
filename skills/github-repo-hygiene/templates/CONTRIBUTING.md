# Contributing

Thanks for helping with OWNER/REPO.

## Questions

Use [Discussions](https://github.com/OWNER/REPO/discussions) for questions. Use issues for bugs, features, and tasks.

## Issues

Search open and closed issues before opening one. Use the bug, feature, or task form. Include a way to see the problem and a version number.

Security reports do not belong in issues. See [SECURITY.md](SECURITY.md).

## Pull requests

1. Fork the repository and create a branch from the default branch.
2. Keep the change focused. Open a second pull request for an unrelated fix.
3. Fill in the pull request template. Link the issue with `Fixes #123` when the pull request should close it. That keyword works when the base branch is the default branch.
4. Open a draft while the work is still moving. Mark it ready when you want review.

Maintainers may ask for a test or a smaller diff. A review that requests changes needs a new push, not a resolved conversation alone.

## Labels

`needs-triage` means nobody has reviewed the issue yet. `needs-info` means the next step is a reply from the reporter. `good first issue` is a change a new contributor can finish with the description alone.
